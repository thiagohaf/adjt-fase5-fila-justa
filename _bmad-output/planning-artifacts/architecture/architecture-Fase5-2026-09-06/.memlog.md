- (version) Java 25 LTS (GA set/2025, suportado até 2028) — runtime alvo para todos os serviços.
- (version) Spring Boot 4.1.1 (ago/2026, Spring Framework 7.0.9) — verificado via web em 2026-09-06.
- (version) Spring Cloud release train 'Oakwood' (compatível com Spring Boot 4.0.x/4.1.x) para Gateway/Config/discovery.
- (version) Spring gRPC 1.0.x (org.springframework.grpc, projeto oficial spring-projects/spring-grpc, suporta Spring Boot 4.1.x) para chamadas internas síncronas.
- (version) PostgreSQL 18 (estável; PostgreSQL 19 ainda em beta em set/2026) — um único cluster, schema por serviço.
- (version) AWS SNS+SQS para mensageria assíncrona (evita MSK, conforme constraint de custo do addendum).
- (version) AWS ECS Fargate para hospedar os serviços (billing por segundo, scale-to-zero ao pausar) + AWS Lambda para o job de seed/Camada Adaptadora (precedente Fase 4).
- (decision) Paradigma: microsserviços com Clean Architecture por serviço (domínio sem dependência de framework) + CQRS lógico (métodos de comando e consulta separados no mesmo serviço/BD; sem read-store dedicado) — conforme addendum.
- (decision) Bounded contexts (Event Storming leve a partir do PRD/addendum): triagem-score-service (Triagem+Score+Paciente/CPF), matching-alocacao-service (Recurso+Sugestão+Alocação+Aging), auditoria-service (Log Auditável, somente-leitura+consumidor de eventos); ingestao-adapter é um job de seed, não um serviço de runtime.
- (decision) Propagação do Score (FR-3) e demais eventos de domínio: Transactional Outbox em cada serviço produtor -> SNS topic -> SQS por consumidor (fan-out). Não-bloqueante para a resposta da Triagem; sobrevive a indisponibilidade do consumidor (mensagem fica na fila).
- (decision) Entrega garantida do Log Auditável (FR-8): SNS+SQS é at-least-once por natureza; auditoria-service deduplica por event_id (idempotência), resolvendo a reconciliação sob falha parcial.
- (decision) [ASSUMPTION] Escala do Score fixada em 0-100. Aging (FR-7): prioridade_efetiva = score + min(k*horas_espera, teto), teto=20 (20% de 100), k calibrado para atingir o teto em 18h simuladas (ponto médio da banda 12-24h) => k≈1.111 pontos/hora.
- (decision) Especificidade de Recurso (FR-5): campo numérico especificidadeRank atribuído no seed; ordem leito comum(1) < leito UTI(2) < leito UTI especializado(3) < especialista(4); sugestão prefere menor rank suficiente para o caso.
- (decision) Duração do atendimento simulado (FR-13): unidade = minutos de relógio real (não horas simuladas aceleradas); default 2-5 min por tipo de Recurso; seed inclui 1 Recurso a <1 min da liberação.
- (decision) Liberação de Recurso (FR-13) implementada via mensagem SQS com delay/visibility-timeout igual à duração do atendimento, publicada por matching-alocacao-service na confirmação (FR-12); ao expirar, o próprio serviço processa a liberação — sem scheduler externo.
- (decision) CPF (LGPD): armazenado em texto claro apenas em triagem-score-service (agregado Paciente), fronteira de ingestão (FR-2). Endpoints gRPC internos ResolveCpfParaId(cpf)->pacienteId e ObterCpfMascarado(pacienteId)->cpfMascarado, consumidos exclusivamente por auditoria-service quando a consulta (FR-9) é feita por CPF; nenhum serviço além de triagem-score-service jamais lê ou retorna o CPF em claro.
- (decision) [ASSUMPTION] Máscara de CPF: mantém os 3 primeiros dígitos e os 2 dígitos verificadores, mascara os 6 do meio — formato 123.***.**9-09.
- (decision) Persistência: um único cluster PostgreSQL 18 (RDS ou container), schema dedicado por serviço, credenciais por schema; nenhuma query cross-schema — acesso a dado de outro serviço só via API pública/evento. Decisão de custo (evita N instâncias RDS) que preserva o isolamento lógico DB-per-service.
- (decision) Autenticação (FR-11): único ponto de aplicação é o Spring Cloud Gateway (Oakwood), validando token mockado (bearer estático) antes de rotear; serviços internos confiam na rede privada/gRPC, sem RBAC (conforme assumption aceita do PRD).
- (decision) Service discovery/config: Spring Cloud Netflix Eureka (discovery) + Spring Cloud Config (config centralizada); comunicação síncrona interna (ex.: ResolveCpfParaId) via Spring gRPC 1.0.x; comunicação assíncrona via SNS/SQS.
- (decision) Deploy: cada serviço como container em AWS ECS Fargate; scripts deploy/pause/destroy (precedente Fase 4) escalam tasks a 0 fora da janela de demo, cortando custo a praticamente zero. Evitados: MSK, RDS multi-AZ permanente, NAT Gateway 24/7.
- (decision) Camada Adaptadora / seed (FR-10): implementada como job único (AWS Lambda ou script de bootstrap, precedente Fase 4) disparado pelo script de deploy; popula dados chamando as APIs públicas de triagem-score-service e matching-alocacao-service — nunca escreve direto no banco de outro serviço, preservando a possibilidade de substituição futura por integração real (SISREG/DATASUS).
- (decision) [ASSUMPTION] Faixas fisiológicas plausíveis (FR-1) para rejeição com 400: FC 40-200bpm, PAS 60-260mmHg, PAD 30-150mmHg, SpO2 50-100%, FR 5-60irpm, Temp 30-42°C — limites de plausibilidade, não diagnósticos clínicos.
- (constraint) Custo: privilegiar Free Tier / billing por uso; evitar MSK, RDS multi-AZ permanente, NAT Gateway 24/7; manter padrão deploy/pause/destroy (herdado do PRD §8 / addendum).
- (constraint) CPF não propaga além da fronteira de ingestão (triagem-score-service); nenhum evento de domínio ou log de auditoria carrega CPF em claro (PRD §8).
- (constraint) Testes: ≥90% JaCoCo na camada de domínio por serviço + mutação PIT + integração (contratos entre serviços/Camada Adaptadora) + aceitação BDD Gherkin/Cucumber-JVM cobrindo o fluxo ponta a ponta (PRD §7).
- (constraint) Sem seleção manual livre de alocação (FR-12) e sem liberação manual antecipada de Recurso (FR-13) — ambos fluxos são exclusivamente automáticos/via confirmação da sugestão do sistema.
- (question) Nenhuma pendência bloqueante herdada do PRD (§10). Os valores concretos de k/teto, faixas fisiológicas, ranks de especificidade, duração de atendimento e máscara de CPF foram fixados nesta fase como decisões [ASSUMPTION] calibráveis — não bloqueiam a criação de epics/stories, mas devem ser revisitados se o comportamento observado no seed de demonstração não corresponder à intenção do PRD.
