## Findings

### Architecture Delta

**Novo serviço `auditoria-service`** (read-side only, consumer SQS FIFO):
- **Dependências:** Consome eventos SNS FIFO via SQS FIFO (mesma infra Epic 2/3)
- **Schema isolado:** `auditoria.decisao_auditoria` com REVOKE cross-schema (Ad-10)
- **Padrão:** Consumer + repositório + query layer (CQRS puro)
- **Integração:** LEFT JOIN com `agendamento_confirmacao.agendamentos` (tolerância a agendamento deletado)

**Camadas.**
- **Domain:** `TipoDecisao` enum (8 valores: NOTIFICACAO, CONFIRMACAO, RECUSA, NAO_CONFIRMADO, LIBERACAO, SUGESTAO_GERADA, REPASSE_CONFIRMADO, SUGESTAO_RECUSADA), `StatusAgendamento` enum (Story 4.4a), `DecisaoAuditoria` entity
- **Application:** 2 query use cases (`ConsultarAuditoriaPaciente`, `ConsultarAuditoriaAgendamento`) — sem commands (read-only)
- **Infrastructure:** Consumer SQS, repositório JPA + adaptor, controller REST, exception handler

### Padrões Arquiteturais

✓ **CQRS maintained:** Zero commands, queries isoladas (Stories 4.1/4.2 read-only; consumer executa transações locais)

✓ **Outbox pattern (Epic 2 compat):** Consumer consome envelope padrão:
```json
{
  "eventId": "...", 
  "eventType": "ConfirmacaoRegistrada", 
  "occurredAt": "...", 
  "version": 1, 
  "correlationId": "...", 
  "payload": {...}
}
```

✓ **Pagination SQL-based:** `LIMIT :limit OFFSET :offset` (não stream skip/limit). Rationale: O(1) RAM vs. O(N) para datasets grandes.

✓ **LEFT JOIN + NULL safety:** Story 4.4a JOINs `agendamento_confirmacao.agendamentos` — if agendamento deletado post-auditoria, JOIN retorna NULL, filtro exclui a linha (comportamento esperado per spec).

✓ **Validação centralizada:** `AuditoriaController` valida enum `statusAgendamento` antes de repositório (RFC 7807 exception handler).

✓ **Índices declarados em migration:** `V1__criar_schema_auditoria_e_tabela_decisao_auditoria.sql`
```sql
CREATE INDEX idx_decisao_paciente_timestamp ON decisao_auditoria(paciente_id, timestamp);
CREATE INDEX idx_decisao_agendamento_timestamp ON decisao_auditoria(agendamento_id, timestamp);
UNIQUE(evento_id) -- constraint via banco
```
