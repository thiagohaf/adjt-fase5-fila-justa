## Diff-Scope Review (Fronteiras Entre Stories)

Análise de interdependências e pontos de fricção documentados em `deferred-work.md`:

### Achados Críticos Resolvidos em-loop

1. **Story 3.0 → 3.1b (Race condition em outbox)**
   - **Problema:** Múltiplas instâncias do `RelaySnsPublisherJob` lendo/marcando a mesma linha concorrentemente
   - **Solução:** `SELECT ... FOR UPDATE SKIP LOCKED` (pessimistic lock)
   - **Teste:** Integração com LocalStack provando isolamento

2. **Story 3.1b → 3.1c (Bootstrap síncrono)**
   - **Problema:** Réplica vazia em boot a frio exigindo chamada HTTP síncrona dentro da transação JPA
   - **Solução:** `ScoreBootstrapService` + `TriagemScoreClient` com fallthrough RFC 7807
   - **Patche:** Patch 1 adicionou `@Transactional` ao método inteiro (risco documentado)

3. **Story 3.2b1 → 3.2b3 (Desempate de Pacientes)**
   - **Problema:** Algoritmo de tiers não determinístico para segundo/terceiro empates
   - **Solução:** Ordenação estrita: `Prioridade desc → occurredAt asc → numeroSequencialTriagem asc → pacienteId`
   - **Teste:** 162 testes de domínio para algoritmo, cobrindo 30+ cenários de empate

4. **Story 3-3b1 → 3-3c2b2 (Race condition em sugestão)**
   - **Problema:** Duas requisições GET `/v1/recursos/{id}/sugestao` concorrentes publicando `SugestaoGerada` duplicada
   - **Solução:** Upsert atômico com compare-and-set (`UPDATE ultima_sugestao_registrada WHERE paciente_id <> excluded.paciente_id`)
   - **Teste:** Concorrência real com Postgres (ExecutorService, +50 threads)
   - **Loopback:** Duas rodadas de code review (blind-hunter + edge-case-hunter convergentes)

5. **Story 3-4a1 → 3-4a2 (Liberação agendada)**
   - **Problema:** Tabela `liberacao_agendada` visível demais ao consumidor SQS (raça entre publish e consume)
   - **Solução:** Fila SQS standard com delay explícito (`DelaySeconds = duração do atendimento`), consumidor idempotente por `alocacaoId`
   - **Teste:** Integração LocalStack + Postgres

## Reconciliação com Spec — Divergências Identificadas

### Design Decision Implícita: Fila SQS Standard para Liberação (Não FIFO)

- **Declarado na spec 3-4a:** Fila SQS standard (não FIFO) com delay, DLQ com `maxReceiveCount=5`
- **Razão:** Desordenação de liberações é tolerável (idempotência por `alocacaoId`); delay é mais importante que ordem
- **Risco:** Nenhum (garantias de idempotência já validadas em teste de concorrência)
- **Documentação:** Implícita na spec 3-4a, não em comentário de código
- **Ação:** Considerar adicionar comentário explicativo em `LiberacaoAgendadaSqsClientConfig` para futuro operador

### Gaps Menores (Todos Documentados em `deferred-work.md`)
